## Urutan penyelesaian yang tersisa

1. Selesaikan QA alur customer, admin, developer, billing, reseller, dan guest/security pada staging; siapkan undangan uji publik serta kredensial Xendit Test Mode, bucket R2 non-production, dan email uji.
2. GitHub environment `staging` memuat `STAGING_BASE_URL=https://staging.tamukita.io` dan `STAGING_INVITATION_PATH=/qa-blueprint-fixture`. `PRODUCTION_HOSTNAMES` opsional untuk memblokir host production tambahan; root `tamukita.io` dan `www.tamukita.io` selalu ditolak oleh workflow. Isolasi network runtime sudah diverifikasi. Fixture staging sudah disegarkan dan foto WebP sintetis berhasil dimuat pada pengukuran LCP #3; uji upload serta R2 non-production tetap terpisah. Pastikan provider hanya memakai akun/data non-production, dan dapatkan konfirmasi kesiapan beban operator sampai 1.000 virtual user sebelum menjalankan `staging-quality` dengan profil `full-load`.
3. Lakukan restore drill dan pemeriksaan monitoring di VPS, selesaikan keputusan operator/legal yang terbuka, lalu jalankan pilot sebelum production.
