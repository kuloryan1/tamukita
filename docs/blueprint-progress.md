## Urutan penyelesaian yang tersisa

1. Selesaikan QA alur customer, admin, developer, billing, reseller, dan guest/security pada staging; siapkan undangan uji publik serta kredensial Xendit Test Mode, bucket R2 non-production, dan email uji.
2. GitHub environment `staging` sudah memuat `STAGING_BASE_URL=https://staging.tamukita.io` dan `STAGING_INVITATION_PATH=/qa-blueprint-fixture`. `PRODUCTION_HOSTNAMES` opsional untuk memblokir host production tambahan; root `tamukita.io` dan `www.tamukita.io` selalu ditolak oleh workflow. Isolasi network runtime sudah diverifikasi; siapkan undangan dengan foto, pastikan provider hanya memakai akun/data non-production, dan dapatkan konfirmasi kesiapan beban operator sampai 1.000 virtual user sebelum menjalankan `staging-quality`.
3. Lakukan restore drill dan pemeriksaan monitoring di VPS, selesaikan keputusan operator/legal yang terbuka, lalu jalankan pilot sebelum production.

Hasil CI dan mock tidak menggantikan verifikasi provider nyata pada VPS atau keputusan operator.
